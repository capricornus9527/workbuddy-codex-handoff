## 索引路径修复（2026-11-01，WorkBuddy 记录）

- 现象：`list` 中部分会话 `available: false`，`extract` 报找不到原文件，但聊天文件仍在磁盘上。
- 定位：`state_5.sqlite` 的 `rollout_path` 有两种陈旧形态。一是带 Windows 扩展长度前缀 `\\?\C:\...`，与本机 `sessions` 根目录做相对路径比较时被判为越界（本机 145 条中 29 条）；二是原文件已就地压缩为 `.jsonl.zst`、索引仍写 `.jsonl`（34 条）。两者叠加使 63 条会话显示不可读。
- 修复：比较前统一去掉 `\\?\` 前缀并按平台折叠大小写；记录路径不存在时接受同源 `.jsonl.zst`（或反向的未压缩文件）。确实取不到才在 `list` 里给出计数警告，`extract` 保留原有扫描回退。
- 验证：`node --test` 16 项通过（新增“索引保留未压缩名”和“扩展长度前缀”两项回归）；本机真实数据 145 条 `available` 全部为 true，抽样提取此前失败的 3 条均正常（含 1 条 `.zst`）。真实聊天标题与正文未写入仓库。

## 接手顺序与提示词提取（2026-11-01，WorkBuddy 记录）

- SKILL.md 把接手过程固定为四步：让用户选定聊天 → 读出内容并向用户复述 → 核对原对话指令与工作区 AGENTS.md → 才动手；用户只说“继续”但未指定聊天时回到候选列表，不自动取最新一条。这套顺序限定在一次接手开始时执行一次，选定后同一对话的后续轮次回到普通协作，不重复列候选与复述。
- 交回 Codex 采用「一句话触发 + 文件自解释」，且收尾时才写交接单：用户多在原对话里接着问，宿主是否重新注入项目规则不可保证，所以不把自动发现当路径，也不在项目 AGENTS.md 或 Codex 任何规则文件里加约定；WorkBuddy 只在回复末尾给出可粘贴的触发语。
- 新增 `extract --mode prompt`：只返回当时的 AGENTS.md／环境上下文注入，按目标去重并保留最后一次，过滤界面标记（`<external_codex_apps_open_page>`），避免每轮重复注入淹没真正的约束。
- 验证：`node --test` 17 项通过（含 prompt 模式与 brief 首条用户消息的区分）；本机真实会话抽样，同一聊天的指令注入由 9 条收敛为 1 条最新 AGENTS.md；跳过测试 0。
